## 1. 목표·대상 (필수)

`src/menu.js`에 `createMenu(anchor, { items, onClose })`를 추가하고, `src/modal.js`의 모달 스택·document 리스너를 오버레이 스택으로 일반화해 메뉴가 맨 위일 때 키·바깥 클릭을 메뉴가 받게 한다. 데모의 "메뉴 열기"가 이를 쓴다. 브랜치 `feat/menu-keyboard` → PR #4.

## 2. 경계·불변식 (필수)

- K1 열면 첫 항목으로 포커스.
- K2 ↓/↑는 항목 사이 이동, 끝에서 반대쪽 끝으로.
- K3 맨 위가 메뉴일 때 ESC → 메뉴만 닫힘, 포커스는 메뉴 버튼, 모달은 열린 채(`getOpenModals()` 불변).
- K4 항목 클릭(키보드 Enter는 버튼 기본 동작으로 click) → `onSelect` 호출, 메뉴 닫힘, 포커스 메뉴 버튼.
- K5 메뉴에서 Tab → 메뉴 닫힘, 포커스는 메뉴 버튼으로 옮긴 뒤 **같은 키 이벤트를 다음 맨 위(모달)에 넘겨** 모달의 Tab 가두기가 그대로 적용(버튼이 모달 마지막이면 처음으로 순환).
- K6 맨 위가 메뉴일 때 메뉴 밖(모달 안 포함) pointerdown → 메뉴만 닫힘. 메뉴 버튼 자체의 pointerdown은 닫지 않음(버튼 click이 토글).
- K7 모달이 닫히면(논리 자손 연쇄) 메뉴도 스택에서 빠지고, 오버레이가 0개면 document 리스너도 0개.
- K8 기존 계약 보존: 기존 테스트 38개 무수정 green, `createModal`·`getOpenModals` 시그니처·동작 불변(`getOpenModals`는 모달만 반환), 스크롤 잠금은 모달만.

## 8. load-bearing 가정

- A1: keydown 캡처 핸들러 안에서 포커스를 옮기고 `preventDefault`를 하지 않으면, 브라우저의 Tab 기본 이동은 **옮긴 뒤의 포커스 요소**를 기준으로 일어난다(K5에서 메뉴 버튼 다음으로 이동). jsdom은 기본 이동을 흉내 내지 않으므로 테스트는 "포커스가 버튼에 있고, 모달 가장자리면 가두기가 개입"까지만 검증하고, 실브라우저 기본 이동은 사용자 확인으로 남긴다.
